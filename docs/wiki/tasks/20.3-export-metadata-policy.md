# Task 20.3: Export Metadata Policy

## Goal

Add explicit export metadata policy choices without mutating originals or implying broad metadata correctness.

## Status

Completed on 2026-06-17. JPEG exports support explicit `minimal`, `preserve`, `remove_gps`, and `remove_all` metadata policies, catalog schema version 11 persists those policy values for settings and presets, export records include metadata policy evidence, and the existing Export dialog exposes bounded policy choices.

## Scope

- Add explicit metadata policy values for export settings and presets:
  - `minimal`
  - `preserve`
  - `remove_gps`
  - `remove_all`
- Keep `minimal` as the default.
- Implement JPEG source metadata handling for local raster exports:
  - `preserve` copies supported source metadata segments into the exported JPEG while keeping SilicaRAW output ICC ownership.
  - `remove_gps` copies supported source metadata but strips EXIF GPS IFD evidence.
  - `remove_all` strips source metadata.
  - `minimal` keeps the current conservative output-owned metadata behavior.
- Record the selected policy and metadata-copy evidence in export records.
- Surface policy choices in the existing Export dialog.

## Non-Goals

- Do not add a broad EXIF/XMP/IPTC editor.
- Do not claim complete metadata preservation across all file formats.
- Do not add RAW decode support, camera support, MLX, MCP, plugin runtime, cloud sync, telemetry, auto-update, Homebrew, or Mac App Store behavior.
- Do not add dependencies unless `docs/DEPENDENCIES.md` is updated.

## Acceptance Criteria

- Export settings and presets persist the selected metadata policy outside edit graph state.
- JPEG exports can preserve source metadata, remove GPS evidence, or remove source metadata according to policy.
- Export records include policy and metadata evidence.
- Original files remain byte-for-byte unchanged.
- UI honestly shows the selected metadata behavior and does not imply broad metadata correctness.

Stop if implementation requires edit graph schema changes, if metadata handling can overwrite originals, if GPS removal cannot be proven with a focused fixture, or if UI copy implies unsupported broad metadata preservation.
