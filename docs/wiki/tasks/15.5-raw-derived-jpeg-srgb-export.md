## Scope

- Export from the full-resolution RAW-derived path, not the preview texture cache.
- Use a dedicated full-resolution RAW export source artifact, not `write_raw_preview_artifact`.
- Do not use `max_edge` or `previews/` cache paths for the RAW export source artifact.
- Embed sRGB ICC.
- Record output SHA-256, source SHA-256, ICC embedded state, ICC profile SHA-256, decoder backend, and profile metadata.
- Keep output path separate from original source path.

## Acceptance Criteria

- RAW-derived JPEG sRGB export is fixture-backed. Class A succeeds when the local legal RAW fixture manifest is present; Class C or D should be covered when the manifest includes it.
- Class E, unknown, or extension-only RAWs write no bytes and create no trusted export row.
- sRGB ICC is embedded and inspectable.
- `export_settings_json` records `source_sha256`, `output_sha256`, `icc_profile_embedded`, `icc_profile_sha256`, `decoder_backend`, `input_profile`, `working_space`, and `profile_metadata_source`.
- Source SHA-256 matches fixture/probe evidence.
- Export cannot overwrite the original RAW source by path or canonical file identity.
- Original RAW pre/post hash unchanged evidence is recorded.
- Viewer texture cache is not the export source, and export can run without opening preview.
- Committed exposure/contrast edits affect RAW-derived export output.
- If Core Image write, ICC inspection, missing profile metadata, or unsupported profile handling fails, no trusted catalog export row is created.
