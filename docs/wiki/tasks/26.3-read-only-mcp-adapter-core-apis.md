# 26.3: Read-Only MCP Adapter Through Core APIs

## Scope

Implement a runtime-free read-only adapter function for the Phase 26 MCP tool manifests.

## Completed Outcome

- `crates/silica-mcp` depends on `silica-core`, not `silica-storage`.
- `run_read_only_mcp_tool` validates the MCP tool manifest before dispatch.
- Supported read-only adapter calls:
  - `silica.photos.list`
  - `silica.photos.get`
  - `silica.photos.get_metadata`
  - `silica.collections.list`
  - `silica.selection.get`
  - `silica.presets.list`
  - `silica.exports.list`
- Photo catalog listing uses Core `query_library_photos` without thumbnail/cache hydration.
- Photo detail uses a Core-owned MCP read helper.
- Metadata, export records, and export preset state use existing Core read APIs.
- Reads append `mcp_read` evidence through Core action-log policy.
- Scope guardrails reject direct `silica-storage`, `rusqlite`, and `open_catalog` use inside `silica-mcp`.

## Non-Goals

- No MCP server.
- No stdio process launch.
- No background listener.
- No HTTP transport.
- No mutation tools.
- No export execution tools.
- No direct SQLite or storage access from `silica-mcp`.
- No permission self-escalation.

## Validation

Use:

```bash
cargo test -p silica-mcp -p silica-core
scripts/harness/check.sh
```

## Next Task

Phase 26 is complete for the read-only-first MCP slice. The next route should enter the public beta gate planning/audit path, keeping MCP disabled unless a future task explicitly enables a server.
