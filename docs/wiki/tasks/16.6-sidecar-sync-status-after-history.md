# Task 16.6: Sidecar Sync Status After History Commits

## Goal

Update sidecar sync status after history commits without silently overwriting conflicts or newer sidecars.

## Scope

- Define and implement sidecar sync status after committed history changes.
- Keep sidecar writes under library `sidecars/`.
- Preserve existing sidecar validation and rebuild dry-run rules.
- Report conflict/newer-sidecar states instead of overwriting silently.
- Do not add sidecar conflict UI beyond status data.

## Acceptance Criteria

- History commits update sidecar sync status only after validated catalog commit.
- Sidecar status survives reopen.
- Newer or conflicting sidecars are reported, not overwritten.
- `sidecar.flags` stays limited to portable culling fields.
- Original photo files remain untouched.

## Validation

```bash
cargo test -p silica-storage -p silica-core
scripts/harness/check.sh
```

## Completion State

Not started.

## Stop Gates

Stop if sidecar sync can silently overwrite conflict state, write outside `sidecars/`, or add catalog-only fields such as `edited` or `exported` to `sidecar.flags`.
