# Task 29.9: Enable CSP and Capability Audit

## Goal

After Task 29.7, replace the desktop application's `csp: null` configuration with a strict Tauri content security policy that permits only required self-hosted assets and module scripts plus `blob:` preview images, and reduce `capabilities/default.json` to the minimum permissions required by the local workflow.

## Scope

- Dependency: Task 29.7 must be complete before this task starts so the final asset and module-script topology is available for audit.
- Replace `csp: null` with the smallest directive set supported by evidence from the post-Task 29.7 desktop runtime. Allow self-hosted application assets and module scripts, and allow `blob:` only where generated previews require it.
- Do not allow remote network origins, wildcard origins, `'unsafe-eval'`, or permissions justified only by possible future behavior.
- Audit `apps/desktop/src-tauri/capabilities/default.json` against the shipped local workflow. Retain only the window bindings and Tauri permissions exercised by that workflow, and remove unused or broad filesystem access.
- Add focused static assertions for the required CSP and capability boundaries without duplicating Tauri's own schema validation.
- Record the exact effective CSP value, capability identifier, window bindings, permission list, removals, and the workflow evidence that justifies every retained source and permission.
- Do not add a permissive alternate policy, conditional CSP disablement, retry path, or speculative compatibility fallback.
- Use only existing dependencies; do not add, update, or replace dependencies.

## Acceptance Criteria

- Desktop configuration no longer contains `csp: null`, and the effective CSP permits only required self-hosted assets and module scripts plus the narrowly scoped `blob:` preview source.
- The CSP contains no remote network origin, wildcard origin, or `'unsafe-eval'` allowance.
- `capabilities/default.json` contains only the minimum window bindings and permissions proven necessary by the local workflow, with no broad filesystem permission.
- Static checks fail if CSP is disabled or broadened beyond the audited sources, or if the removed broad capability permissions return.
- The built and installed app loads all local styles and modules, renders library and Develop previews from blob URLs, completes the local edit/export workflow, and reports no CSP-blocked required resource or command.
- The completion record includes the exact CSP and capability configuration, a justification for every retained allowance, the removed allowances, command results, and installed-app manual QA evidence.
- No dependency, unrelated frontend change, command redesign, or fallback behavior is included.

## Stop Gates

Stop if Task 29.7 is incomplete, a required source or permission cannot be tied to observed local-workflow evidence, the workflow appears to require a remote network origin, wildcard source, `'unsafe-eval'`, broad filesystem access, a new dependency, or a permissive fallback, or the configured policy cannot be verified in an installed app. Record the blocker instead of weakening the boundary.
