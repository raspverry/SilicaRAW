# Task 13.7: Color Metadata Contract

## Goal

Wire color metadata through existing schemas and crate boundaries without inventing hidden fields.

## Read Before Work

- [Phase 13 Color Pipeline Proof Brief](../phases/phase-13-color-pipeline-proof.md)
- [Edit Graph](../topics/edit-graph.md)
- [Schema Reference](../../19_Schema_Reference.md)
- [Edit Graph Schema](../../../schemas/edit_graph.schema.json)

## Files

- `crates/silica-edit`
- `crates/silica-render`
- `crates/silica-export`
- `docs/wiki/topics/color-management.md`

## Scope

- Use `profile.input_profile`, `profile.working_space`, and `profile.decoder_backend` as the edit graph contract.
- Preserve export color metadata in existing export records or documented schema fields.
- Keep parser-owned raw/profile data out of unversioned hidden structures.

## Acceptance Criteria

- No hidden schema fields are invented.
- Existing schema fields remain authoritative.
- Metadata values are explicit, serializable, and test-covered.
- Unknown or unavailable profile data remains explicit instead of guessed.

## Validation

```bash
cargo test -p silica-edit -p silica-render -p silica-export
scripts/harness/check.sh
```

## Completion State

Complete as of 2026-06-12.

Task 13.7 added:

- Explicit `silica-edit` constants for `unknown` input profile and `linear_display_p3` working space.
- `ColorProfileMetadata` and `apply_color_profile_metadata` for evidence-backed writes to schema-owned `profile` fields.
- Validation that `profile.name`, `profile.input_profile`, `profile.working_space`, and present `profile.camera_profile` values are non-empty.
- Default edit graphs now use `profile.input_profile = "unknown"` and `profile.decoder_backend = null`.
- Export records now preserve `output_sha256`, `icc_profile_embedded`, `icc_profile_sha256`, and `profile_metadata_source` in existing `export_settings_json`.
- Schema examples now avoid guessed decoder/profile values.

No new edit graph schema fields or hidden color metadata structures were added.

## Stop Gates

Stop if the existing schema cannot represent the required metadata; update schema docs first instead of adding ad hoc fields.
