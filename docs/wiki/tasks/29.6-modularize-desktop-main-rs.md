# Task 29.6: Modularize Desktop `main.rs`

## Goal

Mechanically split desktop command handlers and data transfer objects out of `apps/desktop/src-tauri/src/main.rs` without changing command registration, names, payload shapes, or behavior.

## Read Before Work

- [LUT and Video Service Master Plan: Phase 29](../roadmaps/lut-video-service-master-plan.md#phase-29-service-foundation-hardening)
- [Architecture Overview](../overview/architecture.md)
- `codex/AGENT_RULES.md`
- `docs/03_System_Architecture.md`
- [ADR 0011: Service Direction Charter](../decisions/adr-0011-service-direction-charter.md)
- The completed Task 29.5 card and implementation diff
- `apps/desktop/src-tauri/src/main.rs`, including its existing tests

## Files

- `apps/desktop/src-tauri/src/main.rs`
- `apps/desktop/src-tauri/src/commands/`
- `apps/desktop/src-tauri/src/dto/`

## Scope

- Dependency: Task 29.0 is complete, and ADR 0011 is accepted. Task 29.5 must be complete before work begins.
- Move existing Tauri command handlers mechanically into `commands` modules and existing request/response data transfer objects into `dto` modules.
- Keep exactly one `generate_handler!` registration list in `main.rs`.
- Preserve every registered command name, Rust command signature, serialized field name, payload shape, response shape, error contract, and invocation behavior.
- Use only existing dependencies; do not add or change dependencies.
- Deliver Task 29.6 alone as one task and one PR. Do not combine it with crate modularization, frontend extraction, command redesign, cleanup, rename, or behavior change.

## Acceptance Criteria

- Command handlers and DTOs are separated into focused `commands` and `dto` modules.
- `main.rs` retains the single `generate_handler!` registration list and application startup wiring.
- The registered command set, command names, payload serialization, response serialization, and runtime behavior remain unchanged.
- Existing desktop tests pass without weakened or removed assertions.
- The diff contains only the mechanical extraction and the import, visibility, module declaration, and test-location adjustments required by that extraction.

## Validation

```bash
cargo test -p silica-desktop
scripts/harness/check.sh
git diff --check
```

## Stop Gates

Stop if Task 29.0 has not been accepted, if Task 29.5 is incomplete, if more than one `generate_handler!` registration list is required, if any command name/payload/response/behavior must change, if a new dependency is required, or if unrelated refactoring cannot be separated into another task and PR.

## Completion State

Completed on 2026-07-11.

Desktop `main.rs` was mechanically split into command modules and DTO modules with no dependency, schema, payload, behavior, startup, original-safety, or public API change.

Command handlers moved into `commands/session.rs` (12 commands), `commands/library_review.rs` (12), `commands/develop.rs` (32), and `commands/export_cache.rs` (10). DTOs moved into `dto/response.rs`, `dto/data.rs`, `dto/session.rs`, `dto/library.rs`, `dto/develop.rs`, `dto/export.rs`, and `dto/activity.rs`.

`main.rs` retains application startup, the installed workflow smoke, tests, and exactly one 66-entry `generate_handler!` list.

Review evidence recorded old/current production top-level definitions at 211 (154 functions, 36 structs, 2 enums, 19 impls), impl methods at 31, missing/extra/body mismatches at 0, 66 command signatures/attributes/bodies identical, registration order identical, 38 DTO types (36 structs, 2 enums) with identical serde surfaces, 9 cfg guards, a byte-identical test module with 46 default active tests, and byte-identical startup and installed workflow smoke.
