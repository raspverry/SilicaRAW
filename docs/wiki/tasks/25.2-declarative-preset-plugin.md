# 25.2: Declarative Preset Plugin

## Scope

Add a safe data-only preset plugin format and one explicit Core approval path for applying a preset.

## Completed Outcome

- `schemas/plugin_preset_pack.schema.json` defines `silica.plugin_preset_pack` v1.
- `silica-plugin` validates data-only preset packs against a validated `preset_pack` manifest.
- Preset packs must match the manifest `plugin_id`.
- Preset packs reject unknown executable fields such as `command`.
- Task 25.2 supports P0 Basic adjustment preset data only.
- `silica-edit` applies plugin preset data through the edit graph validator.
- `silica-core::approve_plugin_preset` requires `edit_suggestion:apply`, explicit approval by caller, commits one undoable history checkpoint, writes plugin provenance under `extensions`, and appends `plugin_apply` action-log evidence.
- No arbitrary executable plugin code, plugin runtime, plugin storage, permission persistence, UI, MCP behavior, sidecar writes, export writes, or original-file mutation was added.

## Validation

Use:

```bash
cargo test -p silica-plugin -p silica-core -p silica-edit
scripts/harness/check.sh
```

## Next Task

Task 25.3 should add the plugin permission review surface/action-log flow around enable/apply decisions. It should not add executable plugin runtime or direct SQLite access.
