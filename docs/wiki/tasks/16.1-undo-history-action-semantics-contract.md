# Task 16.1: Undo, History, and Action Semantics Contract

## Goal

Define exact semantics for undoable actions, redoable actions, logged-only actions, and actions that must never be silently reversed.

## Scope

- Define undo semantics for edit commits, rating, pick/reject, and color label.
- Define logged-only semantics for export, backup, restore, import, cache clear, and sidecar sync actions.
- Define disabled states and user-visible expectations for undo/redo.
- Define what counts as one checkpoint.

## Acceptance Criteria

- Edit commits and culling flag changes are undoable through documented catalog transactions.
- Exports are logged but undo never deletes exported files.
- Cache clearing is logged as disposable-data removal and is not byte-restored by undo.
- Sidecar writes and sync conflict states are not silently reversed.
- The contract explicitly says slider drafts create no undo/history entries.

## Completion State

Complete. Task 16.1 records the `silica.action` payload contract, per-photo checkpoint units, redo invalidation rules, logged-only action policy, disabled undo/redo states, and draft-preview no-history behavior in Action Trust and topic docs.

## Stop Gates

Stop if semantics are ambiguous enough that a later implementation could delete exports, mutate originals, or create history for drafts.
