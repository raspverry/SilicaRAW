# Task 29.5: Modularize `silica-core`

## Goal

Mechanically split `crates/silica-core/src/lib.rs` into focused coordination modules without changing its public API or behavior.

## Read Before Work

- [LUT and Video Service Master Plan: Phase 29](../roadmaps/lut-video-service-master-plan.md#phase-29-service-foundation-hardening)
- [Architecture Overview](../overview/architecture.md)
- `codex/AGENT_RULES.md`
- `docs/03_System_Architecture.md`
- [ADR 0011: Service Direction Charter](../decisions/adr-0011-service-direction-charter.md)
- The completed Task 29.3 and Task 29.4 cards and implementation diffs
- `crates/silica-core/src/lib.rs`, including its existing tests

## Files

- `crates/silica-core/src/lib.rs`
- Extracted module files under `crates/silica-core/src/`

## Scope

- Dependencies: Task 29.0 is complete, and ADR 0011 is accepted. Tasks 29.3 and 29.4 must both be complete before work begins.
- Move existing code mechanically into `library`, `develop`, `export`, `session`, and `permissions` modules, or equivalent boundaries already established by the code.
- Preserve every public path, type, function signature, re-export, visibility contract, and cross-crate call pattern.
- Preserve all command coordination, validation, state transition, error, and test behavior.
- Use only existing dependencies; do not add or change dependencies.
- Deliver Task 29.5 alone as one task and one PR. Do not combine it with another modularization, cleanup, rename, logic edit, or behavior change.

## Acceptance Criteria

- `silica-core` responsibilities are separated into focused modules with `lib.rs` retaining the existing public surface through declarations or re-exports.
- Existing callers compile without public API changes.
- Runtime behavior, validation, state transitions, errors, and cross-crate contracts remain unchanged.
- Existing core tests pass without weakened or removed assertions.
- The diff contains only the mechanical extraction and the import, visibility, re-export, and test-location adjustments required by that extraction.

## Validation

```bash
cargo test -p silica-core
scripts/harness/check.sh
git diff --check
```

## Stop Gates

Stop if Task 29.0 has not been accepted, if Task 29.3 or 29.4 is incomplete, if the split requires a public API or behavior change, if a new dependency is required, or if unrelated refactoring cannot be separated into another task and PR.

Not started.
