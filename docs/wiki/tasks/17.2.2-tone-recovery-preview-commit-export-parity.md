## Scope

- Add visible draft behavior for tone recovery controls where support is honest.
- Commit one undoable checkpoint for tone recovery changes.
- Ensure export uses committed tone recovery state.
- Keep unsupported states explicit.
- Do not add vibrance/saturation, histogram, presets, or broad RAW claims.

## Acceptance Criteria

- Draft preview does not write catalog state.
- Commit writes validated edit state and one undoable history checkpoint.
- Export applies the committed tone recovery state where supported.
- Unsupported or blocked sources remain honest.
- Sidecar status follows Phase 16 rules.

## Completion State

Complete.

- Render requests now carry highlights, shadows, whites, and blacks for preview/export planning.
- JPEG/JPG Develop preview and JPEG export apply the same deterministic local tone recovery adjustment from the validated edit graph.
- Core exposes preview/commit commands for tone recovery; draft preview does not write active edit state or history.
- Tone recovery commit writes one undoable history checkpoint labelled `Tone recovery`.
- Export records `highlights`, `shadows`, `whites`, and `blacks` in export settings for raster and RAW-derived export paths.
- Desktop command responses and static Develop controls expose tone recovery without adding color presence, histogram, presets, broad RAW support, or broad color-correctness claims.
