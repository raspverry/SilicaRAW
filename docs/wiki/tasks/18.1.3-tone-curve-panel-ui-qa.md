# Task 18.1.3: Tone Curve Panel UI and QA

## Goal

Expose tone curve controls in Develop with consistent product UI, responsive layout, and explicit unsupported states.

## Read Before Work

- [Task 18.1.2 Tone Curve Preview Commit Export Parity](18.1.2-tone-curve-preview-commit-export-parity.md)
- [Phase 18 Brief](../phases/phase-18-professional-editing-baseline.md)
- [UI Visual and Responsive QA](../topics/ui-visual-responsive-qa.md)

## Files

- `apps/desktop/static/`
- `scripts/harness/check-static-ui.py`
- `scripts/harness/check-ui-workflow-smoke.py`
- `scripts/harness/run-final-visual-qa.py`

## Scope

- Add the tone curve panel to the existing Develop surface.
- Use existing design tokens, typography, spacing, and compact control patterns.
- Show disabled/blocked states when preview or export support is unavailable.
- Keep channel curve and parametric controls disabled or hidden unless Task 18.1.2 proves end-to-end support for them.
- Keep UI presentation-only; no raw SQL or schema ownership in static UI code.
- Do not add HSL, detail, lens, geometry, masks, or batch sync UI.

## Acceptance Criteria

- Tone curve controls are visible only in supported Develop contexts.
- Compact, desktop, and wide layouts fit without overlap.
- UI commands call existing desktop/core boundaries.
- Undo and redo use existing Core commands only.
- Static smoke covers the tone curve workflow path.

## Validation

```bash
python3 scripts/harness/check-static-ui.py
python3 scripts/harness/check-ui-workflow-smoke.py
python3 scripts/harness/run-final-visual-qa.py
scripts/harness/check.sh
```

## Stop Gates

Stop if the UI must fake curve support, enable unsupported curve modes, create history from drafts, or introduce inconsistent spacing, typography, or hidden durable mutations.
