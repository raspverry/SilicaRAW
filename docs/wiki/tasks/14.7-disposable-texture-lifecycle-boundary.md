# Task 14.7: Disposable Texture Lifecycle Boundary

## Goal

Define a minimal disposable texture lifecycle boundary for the native viewer bridge.

## Read Before Work

- [Task 14.6 Render Request Boundary](14.6-render-request-boundary.md)
- [Metal Render Pipeline Specification](../../08_Metal_Render_Pipeline_Specification.md)
- [Data Safety](../topics/data-safety.md)

## Files

- `apps/desktop/src-tauri/src/native_metal_viewer.rs`
- `crates/silica-render/src/lib.rs`
- `docs/wiki/topics/metal-rendering.md`
- `docs/wiki/topics/data-safety.md` if cache safety rules change

## Scope

- Define disposable texture/cache lifecycle states.
- Define cleanup on photo change, library close, and app close.
- Keep texture cache separate from catalog state.
- Keep cache rebuildable and safe to clear.

## Acceptance Criteria

- Texture lifecycle states are explicit.
- Cleanup behavior is testable.
- No original file path is used as a write destination.
- No catalog or sidecar state is written by texture lifecycle management.

## Validation

```bash
cargo test -p silica-render
cargo test -p silica-desktop --features native-metal-viewer
scripts/harness/check.sh
```

## Completion State

Completed on 2026-06-12.

Task 14.7 added:

- `silica-render` disposable viewer texture identity, drawable size, lifecycle state, and release reason types
- explicit cleanup reasons for photo change, drawable resize, library close, and app close
- a feature-gated desktop `NativeViewerTextureBoundary` wrapper for cleanup on viewer bridge events
- safety helpers proving texture lifecycle management does not write catalog state, sidecar state, original-file destinations, or persistent GPU cache state
- optional feature-on runtime evidence logging through `SILICA_NATIVE_VIEWER_TEXTURE_LIFECYCLE_PROOF`

Recorded macOS evidence:

```txt
[SilicaRAW Native Viewer] state=released release_count=4 last_release=app-closed catalog_write=false sidecar_write=false original_write_destination=false persistent_gpu_cache=false rebuildable=true
```

This task does not allocate real product textures, upload image pixels, decode RAW files, write persistent GPU cache state, mutate originals, write sidecars, or write catalog rows.

## Stop Gates

Stop if texture lifecycle design depends on persistent GPU cache state, original-file mutation, or catalog writes.
