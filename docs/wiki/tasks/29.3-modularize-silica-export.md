# Task 29.3: Modularize `silica-export`

## Goal

Mechanically split `crates/silica-export/src/lib.rs` into focused modules without changing its public API or behavior.

## Files

- `crates/silica-export/src/lib.rs`
- Extracted module files under `crates/silica-export/src/`

## Scope

- Dependency: Task 29.0 is complete, and ADR 0011 is accepted. This DAG prerequisite is satisfied.
- Move existing code mechanically into focused request, encoding, metadata/ICC, and pixel-operation modules, or equivalent boundaries already established by the code.
- Preserve every public path, type, function signature, error variant, re-export, visibility contract, output byte behavior, and hash contract.
- Preserve all validation, original-file protection, ICC handling, metadata behavior, and test semantics.
- Limit edits to code movement and the module declarations, imports, visibility, re-exports, and test locations required by that movement. Do not make logic edits.
- Use only existing dependencies; do not add or change dependencies.
- Deliver Task 29.3 alone as one task and one PR. Do not combine it with cleanup, renaming, behavior changes, or another crate split.

## Acceptance Criteria

- `silica-export` responsibilities are separated into focused modules with `lib.rs` retaining the unchanged public surface through declarations or re-exports.
- Existing callers compile without public API changes.
- Export bytes, profile hashes, metadata evidence, errors, and original-safety behavior remain unchanged.
- Existing `silica-export` tests pass without weakened or removed assertions.
- The diff contains only the mechanical extraction and required import, visibility, re-export, and test-location adjustments.
