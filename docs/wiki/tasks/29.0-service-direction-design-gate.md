## Scope

- Dependency: explicit maintainer direction was supplied, and ADR 0011 accepts the charter. Tasks 29.1-29.12 may start only when the Phase 29 DAG permits them.
- Record that SilicaRAW remains a local-first macOS desktop application, not SaaS, a hosted service, or a network-dependent product.
- Define Phases 29-32 as the required baseline. Require Phase 33 before RAW claims and Phase 35 before video claims.
- Keep Phase 34 optional, deterministic, local-only, and free of network inference.
- Preserve the current `SilicaRAW` identity and `dev.silicaraw.desktop` bundle identifier. Do not assume a fork, rename, or rebrand.
- Preserve Rust Core state ownership and existing crate boundaries. Do not introduce a service runtime.
- Require CSP hardening within Phase 29 without implementing the policy in this task.
- Preserve Q6.3, Q6.4, Task 27.2, and every applicable Phase 28 release gate. The new track must not duplicate, weaken, or bypass them.
- Record ADR acceptance by activating the master plan and updating the current route while keeping inherited release gates visible.
- Make documentation changes only. Do not change code, schemas, dependencies, or product behavior.

## Acceptance Criteria

- ADR 0011 is accepted and states every product, phase, identity, CSP, and inherited release-gate requirement above.
- The ADR distinguishes service-capable local desktop work from SaaS, hosted services, and network dependencies.
- The ADR preserves Rust Core state ownership and existing crate boundaries and does not authorize a service runtime.
- ADR acceptance unblocks only the Phase 29 tasks whose DAG dependencies are satisfied; Phase 30 waits for every Phase 29 task.
- The master plan becomes active and the current route changes only after ADR acceptance.
- No code, schema, dependency, bundle identity, or runtime behavior changes.
