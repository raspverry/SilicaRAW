# Task 20.4: Batch Export Progress and Recent Exports

## Goal

Add honest multi-photo export progress and recent export review without changing the underlying single-photo export safety contract.

## Status

Completed on 2026-06-17. The desktop Export dialog now runs selected-photo exports sequentially with real progress counts and per-photo failure rows, while recent exports come from catalog export records with current output-file existence evidence.

## Scope

- Add a catalog-backed recent export read model ordered by export creation time.
- Include output existence evidence so recent exports do not imply missing files still exist.
- Expose recent exports through Core and the desktop command boundary.
- Let the existing Export dialog export all currently selected photos sequentially by reusing the existing single-photo export commands.
- Show real batch progress count, completed count, and failure rows.
- Refresh recent exports after successful exports.

## Non-Goals

- Do not add a background worker, queue persistence, cancellation system, or retry scheduler.
- Do not change the export file format implementations.
- Do not add broad output naming templates beyond a deterministic per-photo suffix for batch export.
- Do not add RAW decode support, MLX, MCP, plugin runtime, cloud sync, telemetry, auto-update, Homebrew, or Mac App Store behavior.
- Do not add dependencies unless `docs/DEPENDENCIES.md` is updated.

## Acceptance Criteria

- Batch progress uses the real current selected photo ids and increments only after each export attempt resolves.
- Per-photo export failures are visible and reviewable in the dialog.
- Recent exports are read from catalog records and include missing-output evidence.
- Single-photo export behavior remains compatible with existing tests.
- Original files remain byte-for-byte unchanged.

## Validation

```bash
cargo test -p silica-storage recent_export
cargo test -p silica-core recent_export
cargo test -p silica-desktop recent_export export
python3 scripts/harness/check-static-ui.py
```

## Stop Gates

Stop if batch export requires a durable queue, if recent exports need a schema migration, if output existence checks mutate files, or if the UI implies missing output files are still available.
