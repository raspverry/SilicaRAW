# Task 21.5: Advanced Agent Access Preferences

## Goal

Close the Phase 21 Preferences surface with disabled-by-default Advanced access controls that explain future agent, MCP, and plugin permissions without starting any runtime.

## Status

Completed on 2026-06-17 as a gate-safe Preferences task. The Advanced pane now exposes Agent Access, MCP Tools, and Plugin Runtime controls as disabled and unchecked. The UI explains that future access requires explicit permission, Core API boundaries, and action-log evidence. It also states that direct SQLite writes remain forbidden and that Preferences do not start plugin runtime, an MCP server, or an agent bridge.

Runtime permission policy, prompt contracts, MCP tools, plugin runtime, model loading, and agent bridges remain Phase 23 work.

## Scope

- Keep Advanced access controls visible but disabled.
- Keep all Advanced access toggles unchecked/off by default.
- Explain future permission and side-effect requirements in the Preferences UI.
- Keep future mutation paths routed through Core APIs and action-log evidence.
- Add static guardrails proving no runtime start path is introduced.

## Non-Goals

- Do not implement MCP server startup.
- Do not implement plugin runtime startup.
- Do not implement agent bridges.
- Do not add MLX runtime or model loading.
- Do not add permission persistence or prompt contracts before Phase 23.
- Do not add direct SQLite or file-system mutation paths.

## Acceptance Criteria

- Agent access is off by default.
- MCP tools and Plugin Runtime are off by default.
- UI explains permissions and side effects required before future enablement.
- No MCP server, plugin runtime, or agent bridge is started by this task.
- Direct SQLite writes from future extension layers remain explicitly forbidden.
