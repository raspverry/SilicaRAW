# Task 29.10: In-Memory Develop Preview

## Goal

Return Develop preview JPEG bytes directly from memory without the current write-to-disk-then-read-back round trip.

## Read Before Work

- [LUT and Video Service Master Plan](../roadmaps/lut-video-service-master-plan.md#task-2910-in-memory-develop-preview)
- [ADR 0011: Service Direction Charter](../decisions/adr-0011-service-direction-charter.md)
- Task 29.3 and Task 29.5 completion records
- [Architecture Patch](../../20_v1_1_Architecture_Patch.md)
- [Data Safety](../topics/data-safety.md)

## Files

- `crates/silica-export/src/`
- `crates/silica-core/src/`

## Scope

- Dependency gate: Task 29.0 is complete, and ADR 0011 is accepted. Tasks 29.3 and 29.5 must both be complete before implementation starts.
- Add an encode-to-buffer entry point in `silica-export` that produces the same JPEG bytes as the existing fixture-backed disk path.
- Route the `silica-core` Develop preview path through the in-memory encoder so its default path does not write an intermediate JPEG and read it back.
- Keep any disk-cache write optional and explicit. Do not retain the disk round trip as an automatic fallback.
- Preserve existing Develop adjustment, JPEG quality, response, error, and supported-source semantics.
- Preserve original-file protections and all export source/output alias checks.
- Use only existing workspace dependencies. Do not add a dependency or build a fallback system.

## Acceptance Criteria

- In-memory preview bytes are hash-identical to bytes from the previous disk path for the same fixture inputs and settings.
- The default Develop preview path returns JPEG bytes without creating or reading an intermediate preview file.
- Any disk-cache write occurs only when explicitly requested and is not required to return preview bytes.
- Tests cover neutral and adjusted fixture inputs across the supported Develop preview path.
- Original-safety tests prove source hashes remain unchanged.
- Existing `silica-export` and `silica-core` behavior outside the preview transport remains unchanged.

## Validation

```bash
cargo test -p silica-export -p silica-core
scripts/harness/check.sh
```

## Stop Gates

Stop if Task 29.0 is not accepted, either prerequisite task is incomplete, fixture hashes differ, the in-memory path requires a new dependency, an automatic disk fallback appears necessary, or any original-file or output-alias protection would be weakened.

## Completion State

Not started.
