# Task 29.4: Modularize `silica-storage`

## Goal

Mechanically split `crates/silica-storage/src/lib.rs` into focused storage modules without changing its public API, behavior, schema, or migration logic.

- [LUT and Video Service Master Plan: Phase 29](../roadmaps/lut-video-service-master-plan.md#phase-29-service-foundation-hardening)

- `docs/03_System_Architecture.md`

## Files

- Extracted module files under `crates/silica-storage/src/`

## Scope

- Dependency: Task 29.0 is not implemented on this branch. Do not start this task until the Task 29.0 ADR is accepted.
- Move existing code mechanically into `schema`, `migrations`, `photos`, `edits`, `exports`, and `sessions` modules, or equivalent boundaries already established by the code.
- Preserve every public path, type, function signature, re-export, and visibility contract.
- Preserve all behavior, SQL schema definitions, migration ordering and contents, persistence logic, and test semantics.
- Use only existing dependencies; do not add or change dependencies.
- Deliver Task 29.4 alone as one task and one PR. Do not combine it with another modularization, cleanup, rename, logic edit, or schema change.

## Acceptance Criteria

- `silica-storage` responsibilities are separated into focused modules with `lib.rs` retaining the existing public surface through declarations or re-exports.
- Existing callers compile without public API changes.
- No behavior, schema, migration, query, or persistence semantics change.
- Existing storage tests pass without weakened or removed assertions.
- The diff contains only the mechanical extraction and the import, visibility, re-export, and test-location adjustments required by that extraction.
