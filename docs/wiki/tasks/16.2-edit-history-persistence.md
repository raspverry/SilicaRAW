Persist validated edit history checkpoints without changing draft preview behavior.

## Scope

- Add catalog migration for edit history checkpoints.
- Store one validated checkpoint when an edit commit persists.
- Preserve active edit state behavior.
- Ensure draft preview updates write no history rows.
- Add idempotence and reopen tests.

## Acceptance Criteria

- Active edit state and history survive library reopen.
- Every history row references a schema-valid edit graph.
- Slider draft updates create no history rows.
- Re-applying migrations is idempotent.
- Existing libraries migrate without losing current active edit state.

## Validation

```bash
cargo test -p silica-storage -p silica-core -p silica-edit
scripts/harness/check.sh
```

## Completion State

Complete. Task 16.2 adds catalog schema version 6, edit history checkpoint columns/indexing, committed exposure/contrast history rows with validated before/after edit graph payloads, draft no-history assertions, migration idempotence coverage, and reopen persistence tests.

## Stop Gates

Stop if invalid edit graphs can enter history, drafts write history, or migration can orphan active edit state.
