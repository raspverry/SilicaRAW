# Task 29.7: Extract Frontend Modules

## Goal

After Task 29.0 is accepted, mechanically extract the approximately 6,600-line inline application script from `apps/desktop/static/index.html` into native ES modules under `apps/desktop/static/js/`, organized around IPC/shared, library, develop, export, and session responsibilities, without changing behavior or state ownership.

## Read Before Work

- [LUT and Video Service Master Plan: Phase 29](../roadmaps/lut-video-service-master-plan.md#phase-29-service-foundation-hardening)
- The accepted Task 29.0 ADR and implementation diff
- `apps/desktop/static/index.html`
- `scripts/harness/check-static-ui.py`
- `scripts/harness/check-ui-workflow-smoke.py`
- Existing desktop tests that exercise the static UI and Tauri IPC boundary

## Files

- `apps/desktop/static/index.html`
- `apps/desktop/static/js/`
- `scripts/harness/check-static-ui.py`
- `scripts/harness/check-ui-workflow-smoke.py`
- Existing desktop tests directly coupled to the inline script location

## Scope

- Dependency: Task 29.0 must be complete and its ADR accepted before work begins.
- Move executable JavaScript out of `index.html` into native ES modules under `apps/desktop/static/js/`, with focused modules for IPC/shared utilities, library, develop, export, and session behavior.
- Keep existing HTML markup in `index.html`; only replace the inline application script with the native module entry-point reference required to load the extracted code.
- Preserve all Tauri IPC command names and payloads, DOM and Tauri event names and ordering, keyboard shortcuts, state transitions, and stale-preview handling exactly.
- Keep the extraction mechanical. Do not introduce a framework, bundler, behavior or state redesign, UI redesign, or new dependency.
- Adjust static contract and workflow smoke coverage only as required to follow the new module files while preserving existing assertions and workflow expectations.
- Deliver Task 29.7 alone as one task and one PR; do not combine it with feature work, visual changes, command redesign, or unrelated cleanup.

## Acceptance Criteria

- The approximately 6,600-line inline application script is removed from `index.html` and represented by native ES modules under `apps/desktop/static/js/` for IPC/shared, library, develop, export, and session responsibilities.
- `index.html` retains its existing markup and contains no inline application logic beyond the module entry-point reference.
- Application behavior, state ownership, command names and payloads, event wiring and ordering, keyboard shortcuts, and stale-preview behavior remain unchanged.
- No framework, bundler, dependency, UI redesign, behavior redesign, or state redesign is introduced.
- Static UI contract checks and UI workflow smoke checks cover the extracted modules without weakening existing assertions.
- Desktop tests, manual workflow QA, and the full harness pass.

## Validation

```bash
python3 scripts/harness/check-static-ui.py
python3 scripts/harness/check-ui-workflow-smoke.py
cargo test -p silica-desktop
scripts/harness/check.sh
```

Manually launch the desktop app and complete the local workflow from library open or creation through import, grid and culling, preview and develop adjustments, and JPEG export. Confirm event-driven updates, keyboard shortcuts, and stale-preview handling behave exactly as before the extraction.

## Stop Gates

Stop if Task 29.0 is not accepted, if native ES modules cannot load in the supported desktop runtime without a framework, bundler, or dependency, if the extraction requires markup restructuring or UI redesign, if command names, payloads, events, shortcuts, state ownership, or stale-preview behavior must change, or if unrelated refactoring cannot be separated into another task and PR.
