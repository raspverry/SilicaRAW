# 22.3: Migration and Backup Failure Tests

## Goal

Harden the recovery test surface around migration, restore, corrupt backup artifacts, existing-target rollback, missing-target preflight, sidecar conflict preservation, and disposable cache regeneration.

## Scope

- Add storage regression coverage for corrupt backup catalog restore failures.
- Preserve the existing target library when staging validation fails.
- Keep rollback creation after successful staging validation only.
- Verify restored stale cache records can be cleared, disposable cache directories are recreated, and thumbnail/preview cache records can be written again after restore.
- Tie Task 22.3 completion to the existing migration, missing-target, and conflict regression tests instead of adding duplicate broad fallback paths.

## Non-Goals

- Do not add a user-facing restore UI.
- Do not add partial table repair.
- Do not copy original referenced photo files, export output files, or cache bytes into backups.
- Do not change migration schema shape.

## Validation

```bash
cargo test -p silica-storage
cargo test -p silica-storage restore_
cargo test -p silica-storage restores_backup_to_empty_directory_preserving_catalog_state_and_originals
scripts/harness/check.sh
```

## Evidence Map

- Migration survival: `upgrades_empty_catalog_from_first_migration`, `metadata_migration_adds_normalized_columns_and_upsert`, `query_index_migration_adds_normalized_file_type_and_indexes`, and `export_settings_migration_upgrades_existing_catalog`.
- Restore survival: `restores_backup_to_empty_directory_preserving_catalog_state_and_originals` preserves flags, edit state, export records, sidecar status, and schema migration metadata.
- Recoverable missing/corrupt states: `batch_commit_edit_graph_preflight_failure_writes_no_history`, `restore_rejects_newer_schema_backup_without_mutating_existing_library`, and `restore_corrupt_backup_catalog_preserves_existing_target_with_context_error`.
- Conflict states: `history_updates_preserve_conflict_and_sidecar_newer_statuses` and `rebuild_dry_run_reports_conflicts_and_identity_mismatch`.
- Disposable cache regeneration: `restores_backup_to_empty_directory_preserving_catalog_state_and_originals` now verifies stale restored cache records can be cleared, directories are recreated, and new thumbnail/preview cache records can be written under the restored library.

## Result

Completed on 2026-06-17. Corrupt backup catalog restore now returns a recoverable error containing backup and target context, cleans staging state, preserves the existing target, and creates no rollback before staging validation succeeds. Restore success coverage now verifies stale disposable cache records can be cleared, cache directories are recreated, and new thumbnail/preview cache records can be recorded after restore.
