# 24.5: Explicit AI Suggestion Approval

## Scope

Convert stored local AI suggestions into edit state only after explicit user approval.

## Completed Outcome

- `silica-storage` can mark an existing AI result as approved without writing edit history by itself.
- `silica-core` exposes `approve_ai_suggestion` and `reject_ai_suggestion`.
- Approval supports the scoped `basic_exposure_contrast` approval suggestion payload.
- Approval commits one undoable edit checkpoint through the existing edit graph/history path.
- Approval records AI provenance under `edit_graph.extensions["silica.ai_provenance"]` and appends an `ai_approval` action-log row.
- Rejection appends an `ai_rejection` action-log row and leaves edit state/history unchanged.
- Desktop exposes `approve_ai_suggestion` and `reject_ai_suggestion` commands.
- The AI Review UI enables approval/rejection only when a stored result is approvable and unapproved.
- Visual QA includes `M024-ai-approval`.

## Suggestion Payload

Stored AI result output may include this approval payload:

```json
{
  "approval_suggestion": {
    "kind": "basic_exposure_contrast",
    "exposure": 0.35,
    "contrast": 9.0,
    "summary": "Apply conservative clarity compensation."
  }
}
```

The payload is not an edit graph and does not bypass edit validation.
