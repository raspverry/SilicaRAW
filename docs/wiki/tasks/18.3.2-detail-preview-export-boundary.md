# Task 18.3.2: Detail Preview and Export Boundary

## Goal

Define and implement the smallest honest supported detail preview/export behavior, with explicit blocked states where renderer support is not ready.

## Read Before Work

- [Task 18.3.1 Detail Mutators](18.3.1-detail-mutators.md)
- [Phase 18 Brief](../phases/phase-18-professional-editing-baseline.md)
- [Data Safety](../topics/data-safety.md)

## Files

- `crates/silica-render/src/lib.rs`
- `crates/silica-core/src/lib.rs`
- `crates/silica-export/src/lib.rs`
- `apps/desktop/src-tauri/src/main.rs`

## Scope

- Carry committed detail state through runtime requests.
- Implement only detail effects that can be previewed and exported consistently.
- Return explicit unsupported states for effects that cannot yet be rendered honestly.
- If no detail effect can be previewed and exported consistently, keep persistence and UI enablement blocked.
- Commit supported detail changes as one undoable checkpoint.
- Do not add MLX denoise, fallback model paths, or broad quality claims.

## Acceptance Criteria

- Supported detail edits have preview/export parity.
- Unsupported detail controls are blocked or disabled with explicit state.
- Commit writes validated edit state and one undoable history checkpoint.
- Export records detail settings where applicable.

## Validation

```bash
cargo test -p silica-render -p silica-core -p silica-export
scripts/harness/check.sh
```

## Stop Gates

Stop if unsupported detail behavior would be hidden behind no-op success or excessive fallback paths.
