# Task 29.12: Develop Slider Coalescing

## Goal

Measure Develop preview latency and coalesce rapid slider IPC at the smallest bounded interval that preserves the existing under-50-ms perceived-response target.

## Read Before Work

- [LUT and Video Service Master Plan](../roadmaps/lut-video-service-master-plan.md#task-2912-develop-slider-debounce)
- The accepted Task 29.0 service-direction ADR
- Task 29.8 completion record, including the exact dependency-free frontend state-transition harness path and command it records
- Task 29.10 completion record
- [Metal Render Pipeline Specification](../../08_Metal_Render_Pipeline_Specification.md#performance-targets)
- [UI Visual and Responsive QA](../topics/ui-visual-responsive-qa.md)

## Files

- `apps/desktop/static/js/`
- The exact dependency-free frontend state-transition harness file recorded by completed Task 29.8; do not create or select another runner
- `docs/wiki/tasks/29.12-develop-slider-coalescing.md` for the measured completion record

## Scope

- Dependency gate: Task 29.0 is not implemented on this branch. Do not start implementation until Task 29.0 is accepted and Tasks 29.8 and 29.10 are complete.
- Extend only the exact dependency-free frontend state-transition harness and invocation recorded by completed Task 29.8; do not invent a runner or path or broaden the frontend test surface.
- Measure current end-to-end Develop preview latency in the local desktop runtime before selecting a coalescing policy.
- Coalesce only rapid slider preview IPC, using the smallest bounded interval justified by the measurements and the existing under-50-ms perceived-response target.
- Keep control-value updates immediate; coalescing applies to preview IPC dispatch, not the visible slider state.
- Preserve the monotonic stale-response sequence guard for queued and in-flight requests.
- Guarantee that the final slider value is dispatched and rendered after rapid input ends.
- Record the baseline, selected interval, bounded-call evidence, and manual perceived-response result in the task completion update.
- Use only existing workspace dependencies. Do not add a framework, timer library, telemetry, background profiler, or broad scheduling abstraction.

## Acceptance Criteria

- Baseline and post-change timing evidence justify the selected interval; no delay is chosen speculatively.
- The extended Task 29.8 state-transition harness proves a rapid input burst produces IPC calls bounded by the documented policy.
- The same harness proves the final input value is dispatched and rendered.
- A reordered-response case in the same harness proves an older response cannot replace a newer preview because the monotonic sequence guard stays active.
- Manual local desktop QA records perceived response below the existing 50-ms target.
- Non-slider Develop commands and commit semantics remain unchanged.

## Validation

Extend the exact dependency-free frontend state-transition harness at the path recorded by completed Task 29.8 with only the burst-call-bound, final-value, and reordered-response cases required by this task. Run that harness with the exact command recorded by completed Task 29.8; do not substitute a new runner, a new path, or a broader frontend test suite.

After that focused command passes, run the existing full harness:

```bash
scripts/harness/check.sh
```

Run a minimal local desktop drag check and record the measured baseline, selected coalescing interval, IPC call bound, final rendered value, and perceived-response result.

## Stop Gates

Stop if Task 29.0 is not accepted, either prerequisite task is incomplete, completed Task 29.8 does not record an exact dependency-free state-transition harness path and command, that harness cannot cover the three focused cases without a new runner or broader test surface, local runtime timing cannot be measured, no evidence-backed interval meets the existing target, the final value can be dropped, the monotonic stale-response guard would be weakened, or a new dependency or speculative fixed delay would be required.
