# Task 29.1: Detail UI Regression and Truth Audit

## Goal

Audit the disabled Develop Detail controls and their UI/IPC paths so sharpening and noise reduction remain honest unsupported state, not enabled pixel behavior.

## Scope

- Dependency: Task 29.0 is complete, and ADR 0011 is accepted. This DAG prerequisite is satisfied.
- Audit every Detail input, button, event listener, delegated event, keyboard path, clipboard path, frontend invocation, registered IPC command, and response mapping for sharpening and non-MLX noise reduction.
- Keep all Detail controls disabled and keep unsupported preview/export messaging visible.
- Remove every callable frontend path that can invoke Detail preview or commit.
- Preserve schema-valid persisted Detail state and read-only desktop/UI readback so existing libraries remain understandable.
- Treat existing `silica-core`, `silica-render`, and `silica-export` unsupported preview, commit, and export-blocker behavior and tests as read-only evidence. Do not change backend logic in this task.
- Confirm from existing backend evidence that committed non-neutral Detail state remains blocked at export and is never silently ignored.
- Use only existing dependencies. Do not implement sharpening, noise-reduction, MLX denoise, or any other Detail pixel operation.

## Acceptance Criteria

- Sharpening, noise-reduction, and MLX denoise controls remain disabled and clearly unsupported.
- No callable frontend Detail path can invoke sharpening or noise-reduction preview or commit.
- Persisted neutral and non-neutral Detail values remain readable through existing edit-state responses and read-only UI presentation.
- Existing backend unsupported-preview, unsupported-commit, and export-blocker tests and assertions remain unchanged.
- No `silica-core`, `silica-render`, or `silica-export` logic changes, and no Detail pixel behavior is added.
- Desktop and static UI tests pass without weakened assertions.

## Stop Gates

Stop and create a separate task plus an authoritative Phase 29 DAG update if the audit finds a backend boundary violation that requires `silica-core`, `silica-render`, or `silica-export` logic changes. Also stop if Task 29.0 is not accepted, any path would apply Detail pixels, persisted Detail state would become unreadable, a new dependency is required, or the audit expands into unrelated UI or IPC refactoring.

## Completion State

Completed on 2026-07-11.

The audit confirmed that no listener or keyboard/delegated path in the shipped frontend can preview or commit Detail. The generic `clipboardSubsetInputs` change listener includes the disabled Detail checkbox, but it cannot include Detail in a clipboard selection because the checkbox stays disabled and `editClipboardSelection()` requires `checked && !disabled`. Persisted neutral and non-neutral Detail state remains readable through the existing edit-state response and disabled Detail UI readback. HTML/UI and desktop/backend logic were unchanged; no Detail pixels or implementation were added.

Existing unchanged blocker evidence remains anchored by these stable test names:

- `desktop_commands_block_detail_commit_until_renderer_support_exists`
- `blocks_detail_preview_commit_and_export_until_renderer_support_exists`
- `batch_sync_edit_clipboard_blocks_unsupported_detail_without_writes`
- `rejects_non_neutral_detail_preview_and_export_until_renderer_support_exists`

The workflow smoke harness now guards absent callable Detail preview/commit paths, the clipboard lock, and persisted Detail readback.
